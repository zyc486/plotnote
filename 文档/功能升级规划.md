# PlotNote 功能升级规划

本文档涵盖 7 个功能模块的详细设计与实现方案，按优先级排序。

---

## 零、数据架构与多端同步方案

### 现状

所有数据存储在浏览器 IndexedDB 中（Dexie 管理），PC 和移动端是完全隔离的存储。JSON 导出导入只能算手动迁移，不算同步。

### 演进路线

#### 短期：PWA 适配（推荐当前实施）

将 PlotNote 做成 PWA（Progressive Web App），手机浏览器直接访问同一个 URL 即可使用。

**实现内容**：
- 添加 `public/manifest.json`（应用名、图标、主题色、显示模式）
- 添加 `public/sw.js`（Service Worker，缓存静态资源实现离线访问）
- 在 `index.html` 中引入 manifest 和注册 Service Worker
- 在 `src/main.js` 中注册 Service Worker

**效果**：手机浏览器访问后可"添加到主屏幕"，体验接近原生 App，IndexedDB 在手机浏览器中也天然可用。配合自动备份功能，基本够用。

**文件清单**：

| 操作 | 文件 | 说明 |
|------|------|------|
| 新建 | `public/manifest.json` | PWA 应用清单 |
| 新建 | `public/sw.js` | Service Worker 缓存策略 |
| 修改 | `index.html` | 引入 manifest |
| 修改 | `src/main.js` | 注册 Service Worker |

#### 中期：WebDAV 云同步（后续迭代）

用户配置坚果云 WebDAV 账号后，PC 和手机都能读写同一份数据文件。

**原理**：在数据访问层（见下方重构计划）中插入同步逻辑，每次数据变更后上传 JSON 到 WebDAV，打开应用时从 WebDAV 拉取最新数据。

**冲突处理策略**：以最新 timestamp 的数据为准，或者每次同步前让用户确认。

**依赖**：需要先完成下方的"数据访问层重构"。

#### 长期：自建后端（如果发展为正式产品）

Node.js + SQLite/PostgreSQL，或直接用 Supabase/Firebase。需要用户认证系统，开发量大，暂不考虑。

### 数据访问层重构（建议尽早做）

**问题**：目前各 store 直接操作 `db`（Dexie 实例），如果以后要加同步层，改动面会非常大。

**方案**：新建 `src/services/dataService.js`，将所有数据读写收敛到这个 service 层。store 只调用 service 而不直接调 `db`。未来加同步层时，只需在 service 层中间插一个同步逻辑，上层完全不用动。

**dataService 接口设计**：

```javascript
// src/services/dataService.js
export const dataService = {
  // Shows
  shows: {
    getAll: () => db.shows.toArray(),
    get: (id) => db.shows.get(id),
    add: (data) => db.shows.add(data),
    update: (id, data) => db.shows.update(id, data),
    delete: (id) => db.shows.delete(id),
  },
  // Episodes
  episodes: {
    getByShow: (showId) => db.episodes.where({ showId }).toArray(),
    get: (id) => db.episodes.get(id),
    bulkAdd: (rows) => db.episodes.bulkAdd(rows),
    update: (id, data) => db.episodes.update(id, data),
    delete: (id) => db.episodes.delete(id),
    deleteByShow: (showId) => db.episodes.where({ showId }).delete(),
  },
  // Records
  records: {
    getByEpisode: (episodeId) => db.records.where({ episodeId }).toArray(),
    getByEpisodes: (episodeIds) => db.records.where('episodeId').anyOf(episodeIds).toArray(),
    get: (id) => db.records.get(id),
    add: (data) => db.records.add(data),
    update: (id, data) => db.records.update(id, data),
    delete: (id) => db.records.delete(id),
    deleteByEpisode: (episodeId) => db.records.where({ episodeId }).delete(),
    deleteByEpisodes: (episodeIds) => db.records.where('episodeId').anyOf(episodeIds).delete(),
  },
  // Series
  series: {
    getAll: () => db.series.toArray(),
    get: (id) => db.series.get(id),
    add: (data) => db.series.add(data),
    findByName: (name) => db.series.where('name').equals(name).first(),
  },
  // Tags
  tags: {
    getAll: () => db.tags.toArray(),
    add: (data) => db.tags.add(data),
    update: (id, data) => db.tags.update(id, data),
    findByName: (name) => db.tags.where('name').equals(name).first(),
  },
  // GenreHistory
  genreHistory: {
    getAll: () => db.genreHistory.toArray(),
    findByName: (name) => db.genreHistory.where('name').equals(name).first(),
    add: (data) => db.genreHistory.add(data),
  },
  // 完整数据（用于备份/导出）
  exportAll: () => exportToJSON(),
  importAll: (data) => importFromJSON(data),
}
```

**迁移策略**：不需要一次性改完，可以逐个 store 迁移。每迁移一个 store，验证功能正常后再迁移下一个。

## 一、数据安全：自动备份与恢复

### 问题现状

所有数据存储在浏览器 IndexedDB 中（Dexie 管理），清缓存/换浏览器/换设备即永久丢失。当前仅有手动导出/导入 JSON 功能，用户容易忘记备份。

### 方案设计

#### 1.1 自动备份机制

**原理**：在每次数据变更后，自动将完整数据快照存入 localStorage 的专用 key 中。localStorage 与 IndexedDB 是独立存储，清缓存时 IndexedDB 可能被清除但 localStorage 通常保留（取决于浏览器行为），至少提供一层冗余。

**实现位置**：`src/utils/autoBackup.js`（新建）

**备份策略**：
- **触发时机**：每次 `addShow` / `updateShowMeta` / `deleteShow` / `createRecord` / `updateRecord` / `deleteRecord` 执行后触发
- **节流**：使用 `debounce` 延迟 5 秒执行，避免频繁写入（连续操作只备份最后一次）
- **存储 key**：`plotnote_auto_backup`
- **存储内容**：`{ data: <exportToJSON的结果>, timestamp: Date.now(), version: 'v6' }`
- **大小限制**：localStorage 通常有 5-10MB 限制。如果数据超过 4MB，跳过自动备份并打印 warning

**核心代码结构**：
```javascript
// src/utils/autoBackup.js
const BACKUP_KEY = 'plotnote_auto_backup'
const MAX_BACKUP_SIZE = 4 * 1024 * 1024

let backupTimer = null

export function scheduleBackup() {
  if (backupTimer) clearTimeout(backupTimer)
  backupTimer = setTimeout(async () => {
    const json = await exportToJSON()
    const payload = JSON.stringify(json)
    if (payload.length > MAX_BACKUP_SIZE) {
      console.warn('数据量超过 4MB，跳过自动备份')
      return
    }
    localStorage.setItem(BACKUP_KEY, JSON.stringify({
      data: json,
      timestamp: Date.now(),
    }))
  }, 5000)
}

export function getBackupInfo() {
  const raw = localStorage.getItem(BACKUP_KEY)
  if (!raw) return null
  const { timestamp } = JSON.parse(raw)
  return { timestamp }
}

export function restoreFromBackup() {
  const raw = localStorage.getItem(BACKUP_KEY)
  if (!raw) return null
  return JSON.parse(raw).data
}
```

#### 1.2 备份提醒

**实现位置**：`src/pages/ShowList.vue` 的 `onMounted` 中

**逻辑**：
- 页面加载时检查 `getBackupInfo()`
- 如果无备份 → 显示 toast："尚未有自动备份，建议立即导出一份数据"
- 如果有备份且距今 > 7 天 → 显示 toast："上次备份为 X 天前，建议导出一份新备份"
- 首页 header 的"导出"按钮旁添加一个小型备份状态指示器（绿色圆点 = 7天内有备份，黄色 = 7-30天，红色 = 超过30天或无备份）

#### 1.3 自动恢复

**实现位置**：`src/pages/ShowList.vue`

**逻辑**：
- 页面加载时检查 IndexedDB 是否有数据
- 如果 IndexedDB 为空但 localStorage 有自动备份 → 弹出确认框："检测到本地有自动备份（时间：YYYY-MM-DD HH:mm），是否恢复？"
- 用户确认后调用 `importFromJSON(backupData)` 恢复

#### 1.4 集成点

需要在以下 store 方法末尾调用 `scheduleBackup()`：
- `src/stores/shows.js`：`addShow`、`updateShowMeta`、`deleteShow`
- `src/stores/records.js`：`createRecord`、`updateRecord`、`deleteRecord`、`setActiveRecord`
- `src/stores/episodes.js`：`deleteEpisode`

#### 1.5 文件清单

| 操作 | 文件 | 说明 |
|------|------|------|
| 新建 | `src/utils/autoBackup.js` | 自动备份/恢复/提醒逻辑 |
| 修改 | `src/stores/shows.js` | 添加 `scheduleBackup()` 调用 |
| 修改 | `src/stores/records.js` | 添加 `scheduleBackup()` 调用 |
| 修改 | `src/stores/episodes.js` | 添加 `scheduleBackup()` 调用 |
| 修改 | `src/pages/ShowList.vue` | 添加备份提醒 + 自动恢复 + 状态指示器 |

## 二、移动端适配

### 问题现状

- `EpisodeRecord.vue`：左侧栏 `w-72`（288px）固定宽度，手机屏幕（375px）几乎全被左侧占用
- `EpisodeList.vue`：`grid-cols-8` 方格在手机上太小
- `ShowList.vue`：`max-w-2xl` 卡片宽度可接受，但 header 按钮可能溢出
- `Statistics.vue`：统计卡片网格可能溢出
- `Search.vue`：筛选栏和结果列表需要响应式

### 方案设计

#### 2.1 断点策略

使用 Tailwind CSS 标准断点：
- **移动端**：< 768px（sm 以下）
- **平板**：768px - 1024px（md）
- **桌面**：> 1024px（lg 以上）

#### 2.2 EpisodeRecord.vue（改动最大）

**桌面端**：保持现有左右布局（左侧 w-72 + 右侧 flex-1）

**移动端**：改为上下布局
- 左侧评分区域 → 移至顶部，横向排列（评分数字 + slider + 数字输入一行）
- 多刷记录 → 折叠为可展开面板（"多刷记录 (3)" 点击展开）
- 感想区域 → 全宽
- 图片管理 → 全宽
- 底栏导航 → 保持不变

**Tailwind 实现方案**：
```
主体容器：flex flex-col md:flex-row
左侧栏：  w-full md:w-72
评分区域：flex flex-col md:flex-col（移动端改为横向 compact 布局）
```

**移动端评分区域设计**：
```
┌─────────────────────────────┐
│  ← 返回     老友记 S01E03  已保存 │
├─────────────────────────────┤
│  [6.5] ████████░░ [10]     │  ← 评分一行：数字 + slider + 最大值
│  多刷记录 (3) ▼             │  ← 可折叠

│  感想 textarea...           │
│                             │
│  [图片区域]                 │
├─────────────────────────────┤
│  ← 上一集  选择集数  下一集 → │
└─────────────────────────────┘
```

#### 2.3 EpisodeList.vue

**改动**：
- `grid-cols-8` → `grid-cols-4 sm:grid-cols-6 md:grid-cols-8`
- 封面图大小：移动端缩小或隐藏
- header 信息（名称/均分/进度）保持单行但字号缩小

**改动**：
- header 按钮组：移动端部分按钮折叠为"更多"菜单

## 三、观看状态系统

### 问题现状

添加内容后只有一个隐含状态：有评分 = 看过，无评分 = 未看。无法区分"想看""正在看""已看完"三种状态。

### 方案设计

#### 3.1 数据库变更

**升级至 v6**：`shows` 表新增 `status` 和 `startDate`、`finishDate` 字段

```javascript
db.version(6).stores({
  shows: '++id, name, avgRating, ratedCount, category, region, seriesId, coverImage, status',
  // 其余表不变
})
```

**status 枚举值**：
- `null` / `undefined`：未设置（向后兼容旧数据）
- `'want'`：想看
- `'watching'`：在看
- `'finished'`：已看完
- `'dropped'`：弃了

#### 3.2 默认状态逻辑

- 搜索添加 → 默认 `'want'`（想看）
- 手动添加 → 默认 `'want'`
- 评分 > 0 的集数达到总集数的 20% → 提示是否标记为"在看"
- 评分 > 0 的集数 = 总集数 → 提示是否标记为"已看完"
- 以上提示不自动执行，只在用户操作时弹出 toast 带确认按钮

#### 3.3 UI 变更

**ShowList.vue**：
- 分类筛选栏下方新增状态筛选行：`全部 | 想看 | 在看 | 已看完 | 弃了`
- 卡片上显示状态徽章（颜色区分）：
  - 想看：蓝色 `bg-blue-100 text-blue-600`
  - 在看：绿色 `bg-green-100 text-green-600`
  - 已看完：灰色 `bg-gray-200 text-gray-500`
  - 弃了：红色 `bg-red-100 text-red-500`
- 编辑弹窗新增状态下拉选择

**EpisodeList.vue**：
- 名称下方显示状态标签 + 开始/结束日期（如果有的话）

#### 3.4 Store 变更

`src/stores/shows.js`：
- `addShow()` 中 metadata 新增 `status`、`startDate`、`finishDate`
- `updateShowMeta()` 中支持更新 `status`、`startDate`、`finishDate`
- 新增 `updateShowStatus(showId, status)` 便捷方法

#### 3.5 文件清单

| 操作 | 文件 | 说明 |
|------|------|------|
| 修改 | `src/db/index.js` | v6 schema 新增 status/startDate/finishDate |
| 修改 | `src/stores/shows.js` | 新增状态相关方法 |
| 修改 | `src/pages/ShowList.vue` | 状态筛选栏 + 状态徽章 + 编辑表单 |
| 修改 | `src/pages/EpisodeList.vue` | 状态显示 |
| 修改 | `src/utils/exportImport.js` | 导入导出兼容新字段 |

## 四、时间记录与时间线

### 问题现状

`records` 表有 `createdAt`（记录创建时间戳），但前端完全没有利用。不知道什么时候看的、观看节奏如何。

### 方案设计

#### 4.1 数据库变更

**v6 同步升级**：`records` 表新增 `watchedDate` 字段

```javascript
db.version(6).stores({
  // ...
  records: '++id, episodeId, rating, createdAt, watchedDate',
})
```

- `watchedDate`：用户手动设置的观看日期（`YYYY-MM-DD` 格式字符串或 null）
- `createdAt`：记录创建时间戳（自动，不可编辑）
- 区分意义：`createdAt` 是"什么时候录入系统"，`watchedDate`是"什么时候看的"。可能看完一周后才录入。

#### 4.2 EpisodeRecord.vue 变更

在评分区域下方新增一个可选的"观看日期"输入：
- 默认显示"今天"的日期
- 点击可改为任意日期
- 使用原生 `<input type="date">` 实现（无需引入日期库）
- 自动保存到 `watchedDate` 字段

#### 4.3 新页面：时间线（Timeline）

**路由**：`/timeline`
**文件**：`src/pages/Timeline.vue`（新建）

## 五、列表排序与筛选

### 问题现状

首页只有分类筛选（全部/电影/电视剧/动画/图书），不能排序、不能按评分或标签筛选。内容多了以后难以查找。

### 方案设计

#### 5.1 排序功能

在分类筛选栏右侧添加排序按钮组：

| 排序方式 | 说明 | 实现 |
|----------|------|------|
| 添加时间（默认） | 新添加的在前 | 按 `show.id` 降序 |
| 评分高→低 | 高分优先 | 按 `avgRating` 降序 |
| 评分低→高 | 低分优先 | 按 `avgRating` 升序 |
| 名称 A→Z | 按拼音/字母排序 | 按 `name` 升序 |
| 最近观看 | 最近有评分操作的在前 | 需要记录 lastWatchedAt（见 5.4） |

**UI**：排序按钮为下拉菜单，点击展开选项列表，选中项高亮显示。

#### 5.2 筛选功能

在分类筛选栏下方新增一个可折叠的高级筛选面板：

| 筛选维度 | 控件 | 说明 |
|----------|------|------|
| 评分区间 | 双滑块（0-10） | 只显示均分在区间的 show |
| 观看状态 | 多选 checkbox | 想看/在看/已看完/弃了（依赖功能三） |
| 地区 | 下拉选择 | 从已有数据中提取 |
| 类型 | 多选标签 | 从已有数据中提取 |

**UI**：
- 分类筛选栏右侧添加"筛选"按钮，点击展开/收起高级筛选面板

## 六、Markdown 评论

### 问题现状

评论/感想区域是纯文本 textarea，无法排版。写了长评后没有标题、加粗、列表等格式，阅读体验差。

### 方案设计

#### 6.1 技术选型

使用 `marked` 库（轻量级 Markdown 解析器，无依赖，gzip 后约 30KB）。

```bash
npm install marked
```

**不使用**：markdown-it（较大）、showdown（功能过多）。`marked` 足够满足需求。

#### 6.2 渲染策略

采用**编辑/预览双模式**：

- **编辑模式**：保持 textarea 原样（用户写 Markdown 源码）
- **预览模式**：将 Markdown 渲染为 HTML 显示
- **切换方式**：感想区域顶部添加 "编辑 | 预览" 标签切换

**自动保存**仍基于 textarea 的原始文本（Markdown 源码），不影响现有逻辑。

#### 6.3 样式安全

使用 Tailwind CSS 的 `prose` 类（需要 `@tailwindcss/typography` 插件）或手动设置基础 Markdown 样式：

#### 7.3 评分分布计算

```javascript
function calcRatingDistribution(records) {
  const buckets = Array(11).fill(0) // 0, 0.5, 1, 1.5, ..., 10
  for (const r of records) {
    if (r.rating > 0) {
      const bucket = Math.round(r.rating) // 四舍五入到整数
      buckets[bucket]++
    }
  }
  const total = buckets.reduce((a, b) => a + b, 0)
  return buckets.map((count, i) => ({
    score: i,
    count,
    percent: total ? Math.round(count / total * 100) : 0,
  }))
}
```

#### 7.4 类型偏好计算

```javascript
function calcGenrePreference(shows, records) {
  const genreCount = {}
  for (const show of shows) {
    const genres = JSON.parse(show.genres || '[]')
    const showRecords = records.filter(r => /* belongs to this show */)
    for (const genre of genres) {
      genreCount[genre] = (genreCount[genre] || 0) + showRecords.length
    }
  }
  return Object.entries(genreCount)
    .sort((a, b) => b[1] - a[1])
    .slice(0, 10)
    .map(([genre, count]) => ({ genre, count }))
}
```
